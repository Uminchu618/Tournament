# トーナメント表

大会運営者が全参加者の組合せを指定し、勝者を記録できるシングルエリミネーションのWebアプリです。保存して公開した大会は誰でも閲覧できます。A4縦の複数ページを画面と印刷で共通のSVGから描画します。ブラウザーの印刷画面からPDFとして保存できます。

要求と設計は次の文書で管理します。

- [要求分析](要求分析.md)：現状の不足、利用者への質問・回答、受入条件。
- [Cloudflare構成設計書](Cloudflare構成設計書.md)：Workers・D1・Access、複数大会、下書きと公開版、API、移行・復旧の設計。
- [システム設計書（Markdown）](トーナメント表システム設計書.md)：大会・BYE・描画・印刷の設計。

Cloudflare移行後は、招待制の運営者が複数大会を管理し、下書き保存と公開を分け、試合の得点・日時・会場・注記をD1へ保存する方針です。大会は一覧へ掲載せずURLで共有し、PDFの直接ダウンロードを提供します。公開画面は初期設定5分で更新を確認し、手動でも更新できる設計です。

現在のコードは引き続きNode.jsとJSONファイルを使います。以下の起動手順も現行実装用です。

## 起動

Node.js 20以上が必要です。外部パッケージは不要です。

```sh
ADMIN_PASSWORD='12文字以上の強いパスワード' npm start
```

`http://localhost:8080/admin` で編集し、`http://localhost:8080/` で公開画面を確認します。`PORT` で待受ポート、`HOST` で待受アドレス、`DATA_FILE` で保存ファイルのパスを変更できます。標準の待受アドレスは `127.0.0.1`、保存先は `data/tournament.json` です。保存は明示的な「保存する」ボタンで行います。

インターネット公開時はHTTPSのリバースプロキシの背後で起動し、`NODE_ENV=production` を設定してください。永続ディスクに `DATA_FILE` を配置し、定期的にバックアップしてください。パスワードは環境変数で設定し、リポジトリに記録しないでください。

## 操作

1. 運営者画面で大会名と参加者（2〜64名）を登録します。
2. 各枠の選択欄に参加者を割り当てます。配置は自動で決めません。空いた枠はBYEとして扱い、架空の試合は表示しません。
3. 対戦が決まった試合の勝者を選びます。得点の入力はありません。
4. 「保存した内容を一般公開する」を選び、「保存する」を押します。
5. 「印刷・PDF保存」でブラウザーの印刷画面を開きます。A4縦、倍率100%、余白なし、ブラウザーのヘッダーとフッターなしを指定してください。

スマートフォンの運営者画面では「編集」と「表を見る」を切り替えます。表は最初に画面幅に合わせて表示されます。細部を読むときは「拡大して見る」を押し、ページを左右にスクロールしてください。表示倍率を変えても印刷・PDF保存のA4サイズは変わりません。

組合せや勝者の変更で後続結果が無効になる場合は、対象試合を表示して確認を求めます。未完成の組合せは下書きとして保存できますが、一般公開はできません。複数の画面から競合して保存すると、古い画面での保存は拒否されます。

## 検証

```sh
npm test
```

描画エンジンは、提供された `tournament-engine-prototype` を基にしています。元の自動シード配置を、運営者が全枠を指定する方式に変更しました。画面と印刷には同じレイアウト計算結果を利用します。
