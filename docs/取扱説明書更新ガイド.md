# 取扱説明書の更新ガイド

更新日：2026年10月26日

開発で利用者の操作や運用方法を変更した場合は、同じ変更で取扱説明書も更新します。

## 管理する文書

| 文書 | 対象と内容 |
| --- | --- |
| [取扱説明書](../取扱説明書.md) | 主にスマートフォンを使う運営者と閲覧者。大会準備、結果入力、保存・公開、PDF、困ったときの対応。 |
| [システム管理者向け運用手順書](../システム管理者向け運用手順書.md) | システム管理者。導入、運営者管理、バックアップ、障害対応。 |
| [README](../README.md) | 開発者。起動・検証の入口と文書へのリンク。 |

ユーザー確認済みの条件は、読者が運営者・閲覧者・システム管理者、納品形式がMarkdown、当日の入力端末は主にスマートフォンです。アプリ名は仮称「大会トーナメントアプリ」、問い合わせ先の表記は「開発者へ連絡」とします。具体的な連絡手段は未確定です。

管理者向けはCloudflareの知識が全くない読者を前提にします。用語を初出時に説明し、ブラウザーでの作業とパソコンのターミナルでの作業を区別します。各手順には、入力する値、置き換える見本、成功の確認方法、失敗した場合の参照先を記載します。本番用のコマンドは、検証用の文字列を読み替えるだけにせず掲載します。

全体の関係、作業順序、設定先の違いは、必要に応じて図で説明します。管理手順書の図は `docs/images/admin-*.svg` を本文に表示し、その直後の折りたたみ欄に編集用Mermaidコードを保存します。変更時はMermaidコードとSVGを一緒に更新し、表示と手順が一致することを確認します。矢印はデータや操作が実際に進む方向を表し、検証用データが自動で本番へ移るなどの誤解を生まないようにします。

## 変更箇所と説明書の対応

| 変更する実装 | 見直す説明 |
| --- | --- |
| `index.html`、`src/app.js` | ボタン名、画面の移動順、入力・保存・公開の手順、エラーメッセージ。 |
| `styles.css` | スマートフォンの切替・拡大、印刷設定。 |
| `src/model.js`、`src/engine.js` | 参加者数、入力上限、BYE、組合せ、勝者訂正で取り消す情報、ページ分割。 |
| `src/pdf.js`、`src/engine.js` | PDFの対象版、用紙サイズ、ファイル名、試合情報の表示、省略される項目。 |
| `src/auth.js`、`src/worker.js` | ログイン、登録・停止状態、公開画面の更新間隔とエラー対応。 |
| `src/repository.js` | 保存と公開の分離、競合、再送、保存版の保持と復旧上の制約。 |
| `scripts/`、`package.json`、`wrangler*`、`migrations/` | 起動、初回導入、配置、運営者管理、バックアップ、環境の区別。 |

## 更新時の確認

1. 変更した機能を、実装済み、検証済み、未確定のどれに当たるか確認します。設計上の予定だけで利用できるとは書きません。
2. 実際の画面と同じボタン名・項目名で手順を書きます。操作を行う端末と、公開前後で何が変わるかを確認します。
3. 主に使うスマートフォンで、入力欄、キーボード、確認画面、スクロール、保存・公開、PDF保存を確認します。実機で未確認なら、その状態を残します。
4. 関係する既存テストを実行します。画面の操作を変更した場合は `npm run test:e2e` の対象も見直します。リモート環境を使う場合は接続先を確認します。
5. 説明書の相対リンク、見出しへのリンク、入力上限、確認画面で取り消される情報を確認します。
6. 日付と改訂履歴を更新します。未確定項目が決まった場合は、本文と未確定項目の両方を変更します。

文書の変更だけで、同じ動作をなぞるテストは追加しません。認証情報、実際のAPIトークン、バックアップ、個人の連絡先を、確認なく文書へ貼り付けないでください。

## 継続して確認する操作例

| 操作例 | 確認する結果 |
| --- | --- |
| 3組を4枠へ配置し、1枠を空ける | BYEの架空の試合が表示されず、実際の試合だけ入力できる。 |
| 組合せを公開後、大会名や得点を変更して下書き保存する | 公開画面は以前の内容のまま。公開後に更新される。 |
| 前の回戦の勝者・組合せを訂正する | 確認対象の試合が表示され、取り消す項目と残す項目が説明書と一致する。 |
| 2画面で同じ大会を編集する | 古い画面からの保存を拒否し、控えと再読込みで作業を継続できる。 |
| 編集画面と公開画面でPDFを取得する | 下書きと公開版を区別でき、日本語、A4寸法、ページ順を確認できる。 |
| 登録・停止した運営者でログインする | D1とAccessの設定に沿って利用可否が変わる。 |

## 初版の確認記録

2026年10月26日に画面定義、アプリ、モデル、描画、認証、Worker、リポジトリー、管理スクリプト、既存の画面テストのコードを照合しました。並行開発で追加された認証テストを含め、最終確認時の `npm test` は56件すべて成功しました。D1エクスポートとマイグレーションの引数は、インストール済みWranglerのヘルプで確認しました。

説明書作成時には、ブラウザーでのE2E実行、スマートフォン実機検証、Cloudflareへの配置、運営者の登録変更、バックアップ取得、復旧訓練は行っていません。これらを確認した際は結果と環境を追記します。

## 管理者向け0.2版の確認記録

2026年10月26日に、Cloudflareの公式資料でアカウント準備、Zero Trust初期設定、アカウントID、APIトークン、Accessポリシーを確認しました。参照リンクは運用手順書の該当箇所に記載しています。

並行開発で追加された `scripts/backup.mjs` と `scripts/restore-check.mjs` を読み、暗号化バックアップと一時的なローカルD1への復元確認を追記しました。バックアップ鍵の保管と、日次自動実行・本番復旧が別作業であることも記載しています。この文書改訂では、Cloudflareの設定変更やリモートのコマンド実行は行っていません。

## 管理者向け0.3版の確認記録

2026年10月26日に、全体構成、初回準備、環境の区別、運営者の追加・停止、バックアップ、エラー対応の7図を追加しました。本文にあるMermaidコードからSVGを生成し、7図すべてをブラウザーで描画して、文字の折り返しと配置を確認しました。

SVGはHTMLラベルを使わず、文字と図形として出力しています。MarkdownではSVG画像を表示するため、Mermaidを描画する追加機能がないプレビューでも図を読めます。文書内の画像・見出し・相対リンクも確認しています。
